# Notes 验证映射

[English](README.md) | 中文

本目录是验证 Notes 用户可见行为的维护源。操作应用前先阅读索引，再使用对应的功能文件作为操作步骤。

## 基线前置条件

- 使用一次性数据目录，在 `http://127.0.0.1:4173` 启动 Notes。
- 设置 `NOTES_DATA_DIR=/tmp/notes-verify-$RUN_ID`，使并发运行不共享状态。
- 预置标题为 `Quarterly plan` 和 `Grocery list` 的笔记。
- 将 `control-notes` 和 `notes` CLI（命令行界面）加入 `PATH`。
- 运行 `control-notes doctor`，并要求 URL、数据目录和构建修订版本符合预期。
- 绝不操作并非由本次验证运行启动的实例。

## 操作约定

- 除非前置条件另有说明，每组操作步骤都从基线状态开始。
- 优先使用 ARIA 角色和无障碍名称，而非 CSS 选择器或 DOM 位置。
- 将每条命令按字面执行。保持引号中的名称和标志不变。
- 通过 `control-notes browser` 执行浏览器操作。
- 通过 `control-notes cli -- <command>` 执行终端操作。
- 修改后恢复预置数据。清理时不要移除证据产物。

## 证据与跳过报告

- 捕获用户操作及其结果状态，而不只记录最终画面。
- UI 证据包括 ARIA 快照和可见应用标识的截图。
- CLI 证据包括命令、标准输出、标准错误和退出码。
- 修改证据包括对已存储值的第二次只读查看。
- 每份产物都记录所用的功能 ID 和入口。
- 路径无法到达时，报告尝试的命令和未满足的前置条件。
- 不要通过其他路径的验证，将跳过的入口报告为已验证。

## 功能条目约定

每个功能文件以 H1 标题和一段描述用户可见行为的文字开头。随后严格按以下顺序使用四个 H2 节。

1. `Sub-features` 列出简短 ID，每种行为占一行。
2. `How to get to it (user POV)` 列出全部用户入口。
3. `Driving it with <harness>` 以 `Preconditions:` 开头，使用带标签的项目符号，将每项用户操作与确切命令和可观察结果配对。
4. `Gotchas` 列出可能浪费验证时间或使验证失效的陷阱。

映射中不要包含实现细节。仅说明用户路径、稳定的操作标识、必要状态、命令和可观察证据。

## 功能

- [创建笔记](./create-note.md) 涵盖浏览器和 CLI 创建、取消、持久化及清理。
- [搜索笔记](./search.md) 涵盖工具栏、键盘和 CLI 搜索中的匹配、空结果及清除状态。
